# GOOOL20 signup popup and first-order discount (owner decisions, 2026-09-25)

**Offer:** 20% off a customer's first order in exchange for an email
signup. **One person, one use.**

**Designs chosen by the owner:** 1a "split stadium" on desktop, 1e
"mobile bottom sheet" on phones. 1d "red terrace" was considered and
passed over so the popup reads as one system with the dark, crowd-image
panel on both screen sizes. Source files:
`goool advertising/goool20 discount/goool-advertising/email-popup/`
(git-ignored campaign assets; not imported by app code).

## How "one person, one use" is enforced, and where it is not

| Case | Enforced? | How |
|---|---|---|
| Same code used twice | Yes, by Stripe | Every signup gets its own promotion code, `GOOOL20-XXXX`, with `max_redemptions: 1`. There is no shared code; the plain `GOOOL20` code created earlier in test mode was deactivated. |
| Same email signs up again | Yes | The ledger (`discount_codes`, migration 0036) keys on a SHA-256 of the normalised email (lowercase, gmail dots and `+tags` removed). A repeat signup gets the same code back, or "already used" once it is redeemed. |
| Same person, new email | Detected, not blocked | Stripe's hosted Checkout only reveals the name and shipping address after payment, so nothing can refuse the discount beforehand. The webhook records the buyer's name and a normalised address key on the redemption, and the `discount_repeat_flags` view lists any redemption sharing a name or address with an earlier one. Ops can refund or refuse those. |
| Codes left lying around | Expire | Each code expires 30 days after issue. |

Stripe's `first_time_transaction` restriction is also set on every code,
which limits it to a Stripe customer with no prior successful payment.

## What was built

| Piece | Where | Notes |
|---|---|---|
| Popup | `src/components/DiscountPopup.tsx`, mounted once in `src/app/layout.tsx` | Client component. Shows 6 s after load on every page except /cart, /success, /gate, /track-order. Close or Escape hides it for 30 days; a completed signup hides it for good (localStorage, guarded). Focus lands in the field, body scroll locks, `role="dialog"`. Uses the existing `/hero-crowd.webp` and the white lockup in `/brand/`. Listens for the `goool20:open` window event so the header link can reopen it regardless of dismissal. |
| Header link | `src/components/Header.tsx`, `src/components/MobileNav.tsx` | A gold "20% off" text link, not a "Sign up" button: the store has no accounts and that word would promise one. |
| Issue route | `src/app/api/discount/route.ts` | Subscribes the address to Mailchimp with tags `waitlist`, `goool20` first, then issues the code. If the ledger or Stripe is unavailable the visitor is told the code is coming by email rather than shown a code that does not exist. |
| Discount library | `src/lib/discount.ts` | Email normalisation and hashing, coupon lookup/creation, single-use code issue with race handling, `markRedeemed` for the webhook. |
| Mailchimp helper | `src/lib/mailchimp.ts` | Shared by the footer signup and the popup. |
| Webhook | `src/app/api/stripe-webhook/route.ts` | On a paid session with a discount, records the promotion code, session, buyer name and address key in the ledger. Best effort; never blocks an order. |
| Checkout | `src/app/api/checkout/route.ts` | `allow_promotion_codes: true`, so Stripe's page shows the promo field and validates the code itself. |
| Ledger | `supabase/migrations/0036_discount_codes.sql` | Table plus the `discount_repeat_flags` ops view. RLS on, service role only. |
| Stripe script | `scripts/create-goool20-promo.mjs` | Idempotent: ensures the shared 20%-once coupon, deactivates any shared `GOOOL20` code, reports issued codes. Run with the live key when live Stripe is confirmed. |
